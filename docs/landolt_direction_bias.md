# ランドルト環の方向回答に見られる偏り — clef / clef-flash / jev の比較

対象データ: 3 モデル全量実行（2,496 呈示、2026-10-25 実施。所要約 20 分）
生データ: 実行時に `artifacts/benchmark/` へ出力される（リポジトリには残していない。§7 のコマンドで再取得できる）

## 要旨

* **clef** と **clef-flash** は、誤答が**ほぼ 1 つの向きに集中する**。
  誤答のうち最多の向きが占める割合（以下「誤答の集中度」）は **clef 98%（下）**、
  **clef-flash 93%（左）**。方向別正答率の最大差は 38 ポイント・77 ポイント。
* **jev** にはこの集中がない（誤答の集中度 **51%**、方向別正答率の最大差 **17 ポイント**）。
  ただし上下（60%）が左右（40%）より多い**弱い傾向**は統計的に有意（χ²=8.5, df=1）。
* 偏りは「**見えないときの既定の答え**（prior）」として働く。明瞭な画像（清明）では
  clef・jev は **100%** 正解、最大確率が 0.8 以上の呈示は **3 モデルとも 100% 正解**。
  一方 **clef-flash は清明でも 40%** しか当たらず、偏りが知覚を上書きしている。
* 偏りは、選択肢の並び順・回答キーの語彙・質問の言い回し・画像のぼけの異方性では
  説明できない（§4.3）。**モデル自身の回答分布に内在する性質**である。
* 実務的な切り分けは「**最大確率 0.8 以上だけを採用する**」で、3 モデルとも 100% 正解。

## 1. 目的

ランドルト環（切れ目のある環）の切れ目の向きをモデルに判定させると、向きによって正答率が偏ることがある。
方向ごとに正答率が大きく違うと、検査として使うときに「どの向きを測っているのか分からない」問題が生じる。
本レポートは、同じ条件で 3 モデルを測り、**偏りの有無・大きさ・性質**を比較して、
検査や評価に使える形で示す。

## 2. 方法

### 2.1 対象モデル

| モデル | 実行環境 | 規模・量子化 | 備考 |
|---|---|---|---|
| clef | ローカルの System One 互換 API | 27B / Q4_K_M | vision + decision |
| clef-flash | ローカルの System One 互換 API | 9.1B / Q8_0 | vision + decision |
| jev | OpenRouter 経由の System One API | ホスト提供（測定日に確認した応答のモデル名は `typesafe/jev-1.14-*`） | 参照モデル |

### 2.2 呈示条件（2,496 呈示 = 832 呈示/モデル）

| 項目 | 内容 |
|---|---|
| 画像 | 640 × 640 px の PNG。背景は白、環は黒。切れ目は上下左右の 4 方向のみ |
| 形状 | ISO 8596（外径 : 内径 : 切れ目 = 5 : 3 : 1）、輪郭は画素の被覆率でアンチエイリアス |
| 生成モード | 清明（無加工）/ 近視（ガウシアンブラー）/ 混濁（平滑化＋コントラスト低下）/ 乱視（方向性ぼかし、既定角 0°） |
| 視力値 | 2.0, 1.5, 1.2, 1.0, 0.9, 0.8, 0.7, 0.6, 0.5, 0.4, 0.3, 0.2, 0.1（外径 px = 52.7 / 視力値） |
| 方向 | 上 / 下 / 左 / 右 |
| 反復 | 各条件 4 回（**同じ画像を繰り返す**） |
| 組み合わせ | モデル 3 × モード 4 × 視力値 13 × 方向 4 × 反復 4 = **2,496 呈示** |

### 2.3 質問の形式

正解は送らず、画像だけを提示して次の 1 問を投げる（4 択）。

> 提示した画像のランドルト環の切れ目は、上下左右のどの方向に開いていますか？

選択肢（回答キーとその説明）: `up`=上の部分が開いている / `down`=下の部分が開いている /
`left`=左の部分が開いている / `right`=右の部分が開いている。
回答は選択肢のキー、各キーの確率、確信度（最大確率）として記録される。

### 2.4 集計と指標

* **方向別正答率**: 提示した向きごとの正答率。その**最大差**を偏りの大きさの指標にする。
* **回答ラベルの分布**: 回答した向きの件数。4 方向で一様かどうかを **χ² 検定**（df=3、5% 臨界値 7.81）で確かめる。
* **混同行列**: 提示した向き × 回答した向き。
* **誤答の集中度**: 誤答のうち最多の向きが占める割合（0.25 なら一様、1.0 なら完全な単一方向への崩壊）。
* **回答キーごとの平均確率**: モデルが各向きをどれだけ「押している」か。
* **確信度別正答率**: 最大確率の帯ごとの正答率（実運用の切り分けに使えるか）。
* **反復の一致**: 同じ画像 4 回で回答が変わらないか（再現性）。

反復 4 回は同一画像の繰り返しなので、**統計は重複を除いた 208 呈示/モデル**（4 モード × 13 視力値 × 4 方向）で
評価する。反復は再現性の確認と、確率的なモデル（後述）の揺れの把握に使う。

## 4. 考察

### 4.1 偏りは「見えないときの既定の答え」として働く（clef / jev）

* clef と jev は **無加工（清明）で 100%**、環が大きい条件（視力 0.4 以下）でも 100% 正解。
  一方でぼけ・低コントラスト・小さい環では正答率が落ち、その落ち方が**特定の向きに偏る**。
* 確信度別でも同じ構造が見える: 最大確率 0.8 以上の呈示は **clef 456/456・jev 454/454 とも 100% 正解**で、
  誤りは低確信の呈示に集中する。
* つまり「見えているのに間違える」のではなく、**判断材料が乏しいときに既定の答えへ倒れる**。
  この性質は、確信度を使って「判定不能」を切り分けられることを意味する。

### 4.2 clef-flash は偏りが知覚を上書きする

* clef-flash は**無加工でも 40%**、最大の環（視力 0.1）でも 94% で、left を提示したときだけ 100% になる。
* 「見えれば正しい」という関係が成り立たず、**既定の答え（左）が知覚の結果を置き換えている**。
  方向判定の用途では、このモデルは適さない。

### 4.3 偏りを説明しない要因

同じ画像・同じ質問で、別の条件でも測定した（重複を除く 96 呈示/モデル。`--question` の変種を使い、
生成物は上記と同じく実行時に `artifacts/benchmark/` へ出力される）。

| 測定 | clef | clef-flash | jev |
|---|---|---|---|
| 既定（上/下/左/右） | 最多キー `down`=58（その説明=下） | 最多キー `left`=74（左） | 上=33 / 下=28（ほぼ一様） |
| 説明の提示順を逆に | 既定と**完全一致**（両モデル合わせて 192 呈示すべて同じ） | 同左 | 上=41（順序を変えても上に偏る） |
| 中立キー（a/b/c/d）に変更 | `b`=49（説明=**下**） | `c`=72（説明=**左**） | `b`=30（説明=下） |
| 説明文を入れ替え（キーと説明が食い違う） | `up`=50（その説明=**下**）へ移動 | `left`=56 のまま（その説明=右） | `up`=41（その説明=下）へ移動 |
| 反対質問（切れ目が開いていない側を尋ねる） | `down`=53（その説明=下側がつながっている）＝主張が反転 | `left`=66（説明=左側がつながっている） | （未測定） |
| 正答率の幅（既定・中立キー・順序逆・説明入替・反対質問・日本語キー・別語彙を通した範囲） | 55〜67% | 41〜46% | 71〜74% |

読み取れること:

1. **並び順ではない**: 説明の提示順を逆にしても clef / clef-flash の回答は 1 件も変わらない。
2. **回答キーの語彙でもない**: キーを a/b/c/d・かな・上/下/左/右 に変えても、落ち先は
   「**下（または左）と書かれた説明の選択肢**」に付いていく（同じ 4 方向の語彙の範囲）。
   方位語（north/south/west/east）のような別語彙に変えると**どの選択肢に落ちるかは変わる**が、
   誤りが少数の選択肢に集中する性質は残る。
3. **質問の言い回しでもない**: 反対質問では「下側がつながっている」という選択肢を選ぶため、
   切れ目の向きで見た主張は反転する。つまり固定された知覚ではなく、**説明文の中身への選好**である。
4. **画像側の要因でもない**: 乱視（既定角 0°）は縦のエッジ（上下の切れ目）をより強くぼかすため、
   もし画像側の影響なら上下の正答率が下がるはずだが、実際は clef の下は 98%、clef-flash の左は 100% で、
   偏りの向きはぼけの異方性と一致しない。加えて、乱視だけを外しても偏りは清明以外の全モードで同じ形で現れる。
5. **言い回しの工夫では改善しない**: 6 種類の質問変種（中立キー・日本語キー・逆順・説明入替・反対質問・
   別語彙）で正答率はほぼ変わらない。

### 4.4 偏りの判定基準の目安（この測定での実測値つき）

| 指標 | 崩壊している例 | 弱い偏りの例 |
|---|---|---|
| 誤答の集中度 | clef 98% / clef-flash 93% | jev 51% |
| 方向別正答率の最大差 | 38 pt / 77 pt | 17 pt |
| 回答分布の χ²（df=3） | 83.4 / 238.8 | 10.9（有意だが効果は小さい） |
| 最大の回答ラベルの割合 | 52% / 71% | 32% |

### 4.5 モデル間の関係（208 呈示）

| 比較 | 同じ回答になった割合 |
|---|---|
| 3 モデルすべて一致 | 83/208 (40%) |
| clef と jev | 164/208 (79%) |
| clef と clef-flash | 84/208 (40%) |
| clef-flash と jev | 88/208 (42%) |

clef と jev は最も似ている（ともに誤りが下へ寄る）。clef-flash は独立した挙動。

## 5. 実務的な含意

1. **確信度で切り分ける**: 3 モデルとも「最大確率 0.8 以上」は 100% 正解。
   しきい値を入れて低確信を「判定不能」にすると、偏りの影響を避けられる。
   該当する呈示の割合は clef 456/832（55%）、clef-flash 132/832（16%）、jev 454/832（55%）。
2. **平均正答率だけで評価しない**: clef の 72% は「下 98%・上 60%」の平均であり、
   検査として使うと向きによって当たりやすさが大きく違う。**方向別の内訳を必ず併記する**。
3. **モデル選択**: 方向判定に clef-flash を使わない（50%、最大差 77 ポイント）。
   偏りが小さいのは jev（78%、最大差 17 ポイント）。ただし jev は確率的なので反復を入れて評価する。
4. **改善の見込み**: 言い回し・キー語彙の変更では偏りは消えない。
   偏りを減らすには、モデル側（別の量子化・決定用の再調整）か、
   運用側（確信度しきい値・複数回提示の多数決・向きごとの正答率の重み付け）で対処する。

## 6. 限界

* 確率・確信度は API が申告した値であり、その計算方法は実行環境（ローカル実装・OpenRouter）に依存する。
* 3 モデルで経路が異なる（clef / clef-flash はローカルの System One 互換 API、jev は OpenRouter）。
  画像の渡し方も実装差がある（前者は画像配列、後者は state 配列の画像 URL）ため、
  モデル以外の差を完全には排除できていない。
* 反復は「同じ画像の繰り返し」であり、画像の多様性は 208 通り（モデルあたり）である。
* 質問は 4 択 1 問の形式（§4.3 の変種を除く）。他の形式（2 択・自由記述）での挙動は未確認。
* jev は確率的で、モデルの版が更新されると結果が変わりうる（本測定の応答は `typesafe/jev-1.14-*`）。

## 7. 再現方法

```powershell
# 3 モデル全量（2,496 呈示 = モデル 3 × モード 4 × 視力値 13 × 方向 4 × 反復 4）
python -m systemone_vision_test.benchmark
# 全量実行の一部（例: 視力値 1 段階のみ）
python -m systemone_vision_test.benchmark --visions 0.5 --repeats 1
```

* jev（OpenRouter 経由）を含むため、実行には接続先と API キーの設定が要る
  （`python scripts/show_jev_config.py` で解決結果を確認できる）。
  ローカルの 2 モデルだけを測る場合は `--models clef clef-flash`。
* 出力: `artifacts/benchmark/benchmark_<日時>.md`（実行条件・結果表・診断表）と同名の `.json`（生データ）。
  本レポートの数値は 2026-10-25 実施の 3 モデル全量実行（2,496 呈示、所要約 20 分）に基づく。
* 質問の変種（§4.3）は `--question neutral` / `japanese` / `reversed` / `swapped` / `closed` などで測れる。
